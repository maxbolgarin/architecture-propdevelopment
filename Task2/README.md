# Задание 2. Разработка проверочного листа по безопасности данных


### Разделы проверочного листа

1.  **Аутентификация и Авторизация:**
    *   **Обоснование:** Это фундаментальный аспект безопасности. Необходимо убедиться, что только легитимные пользователи (клиенты, собственники, сотрудники) имеют доступ к системам, и что их права соответствуют принципу наименьших привилегий. Учитывая использование Active Directory для сотрудников и Keycloak (auth-service-1) для клиентов, важно проверить консистентность и надежность этих механизмов. Проблемы с отображением чужих данных в ЛК могут быть связаны с ошибками авторизации.

2.  **Управление доступом к данным:**
    *   **Обоснование:** Это *ключевая* проблема компании ("Нарушен контроль данных", "нет ограничений на доступ к данным со стороны систем обработки данных"). Необходимо проверить, как приложения и пользователи получают доступ к данным в базах данных.

3.  **Безопасность API (внутренних и внешних):**
    *   **Обоснование:** Используются API для взаимодействия между микросервисами, с внешними продуктами. Явно указаны проблемы с API партнеров (избыточные данные, недостаточный контроль доступа). Необходимо проверить аутентификацию, авторизацию, валидацию ввода/вывода, защиту от атак.

4.  **Управление секретами:**
    *   **Обоснование:** Системы используют учетные данные для доступа к БД, ключи API для интеграций. Небезопасное хранение или передача этих секретов представляет критический риск. Необходимо проверить, как управляются эти секреты.

5.  **Шифрование данных:**
    *   **Обоснование:** Для защиты конфиденциальных данных при передачи и хранении необходимо использовать шифрование. Это также требование законодательства (152-ФЗ). Нужно проверить использование TLS/SSL для сетевых соединений и шифрование данных в БД.

6.  **Мониторинг и логи:**
    *   **Обоснование:** Для расследования инцидентов и отслеживания аномального поведения пользователей необходим мониторинг событий безопасности.

7.  **Резервное копирование и восстановление (Backup & Recovery):**
    *   **Обоснование:** Упомянуто, что резервное копирование выполняется. Необходимо проверить полноту охвата, актуальность, возможность и регулярность тестирования восстановления.
