# Задание 1. Разработка проверочного листа по безопасности данных

### **1. Классификация данных (на основе ISO 27001/27002):**

*   **Публичные данные:**
    *   Маркетинговые материалы.
    *   Публично доступные списки недвижимости.
    *   Публичные объявления от управляющей компании.
*   **Внутренние данные:**
    *   Руководства для сотрудников.
    *   Аналитические отчеты.
    *   Детальный статус объектов недвижимости.
    *   Графики обслуживания зданий.
*   **Конфиденциальные данные:**
    *   Персональные данные сотрудников, клиентов и собственников.
    *   Данные бронирований при связи конкретного лица с конкретным объектом недвижимости.
    *   Финансовые данные, данные сделок.
    *   Учетные данные пользователей системы.
*   **Секретные данные:**
    *   Ключи API и учетные данные для критически важных внешних систем (Гос. органы регистрации, платежный шлюз).
    *   Администраторские учетные данные для инфраструктуры.
    *   Приватные ключи шифрования.

### **2. Определите риски для каждой категории данных:**

*   **Публичные данные:**
    * **Риск: Искажение** [Оценка: Незначительный] - Искажение публичных данных может вызвать небольшой репутационный ущерб.
    * **Риск: Некачественные данные** [Оценка: Незначительный] - Низкое качество публичных данных может вызвать небольшой репутационный ущерб.

*   **Внутренние данные:**
    * **Риск: Утечка** [Оценка: Значительный] - Утечка внутренних данных может раскрыть конкурентам бизнес-процессы и аналитику, что потенциально снижает конкурентное преимущество.
    * **Риск: Искажение** [Оценка: Значительный] - Искажение руководств может привести к неправильным действиям сотрудников, а искажение аналитики - к неверным бизнес-решениям.
    * **Риск: Потеря** [Оценка: Значительный] - Потеря некоторых внутренних данных приведет к задержкам в работе.

*   **Конфиденциальные данные:**
    * **Риск: Утечка** [Оценка: Критический] - Утечка персональных данных клиентов или финансовой информации может привести к суду, штрафам и репутационному ущербу.
    * **Риск: Искажение** [Оценка: Критический] - Искажение финансовых данных или информации о сделках может привести к неправильным финансовым решениям и юридическим последствиям.
    * **Риск: Потеря** [Оценка: Критический] - Потеря данных о клиентах или финансовых транзакциях может замедлить бизнес-процессы и привести к невозможности выполнения обязательств.
    * **Риск: Некачественные данные** [Оценка: Значительный] - Ошибки в персональных данных могут привести к проблемам с обслуживанием.

*   **Секретные данные:**
    * **Риск: Утечка** [Оценка: Критический] - Компрометация ключей API или учетных данных администраторов может привести к захвату систем, массовым утечкам данных и катастрофическим последствиям для бизнеса.
    * **Риск: Потеря** [Оценка: Критический] - Потеря приватных ключей шифрования может сделать невозможным доступ к зашифрованным данным, что может привести к полной потере критически важной информации.
    * **Риск: Искажение** [Оценка: Критический] - Изменение учетных данных администраторов или ключей API может привести к несанкционированному доступу к системам и их компрометации.

**Структура интеллект-карты (Концептуальная):**

```
Центр: Безопасность данных PropDevelopment

Уровень 1: Категории данных
    -> Публичные данные
    -> Внутренние данные
    -> Конфиденциальные данные
    -> Секретные данные

Уровень 2: Примеры данных (Под каждой категорией)
    -> Публичные данные
        - Маркетинговые материалы
        - Общие описания объектов недвижимости
        - Публичные объявления УК
    -> Внутренние данные
        - Внутренние процедуры
        - Анонимные отчеты
        - Детальный статус объектов (внутренний)
        - Нечувствительные логи
        - Исходный код (некритичный)
    -> Конфиденциальные данные
        - ПДн Клиентов (ФИО, тел, email+)
        - ПДн Собственников (ФИО, тел, email, адрес+)
        - Данные бронирований
        - Данные онлайн-сделок (финансы, контракты)
        - Данные платежей ЖКУ
        - Учетные данные пользователей (логины, хеши паролей)
        - ПДн Сотрудников
        - Финансовые записи
        - Детальные BI-отчеты
        - Чувствительные логи
        - Данные по Умному дому (привязанные к ПДн)
    -> Секретные данные
        - Ключи/учетки API (ГосОрганы, Платежи)
        - Учетные данные администраторов систем
        - Приватные ключи шифрования
        - Стратегические планы

Уровень 3: Риски и Оценка (Под каждой категорией)
    -> Публичные данные
        - Риск: Искажение [Оценка: Незначительный]
        - Обоснование: Искажение публичных объявлений может вызвать временную путаницу или небольшой репутационный ущерб, легко исправляется.
        - Риск: Некачественные данные [Оценка: Незначительный]
    -> Внутренние данные
        - Риск: Утечка [Оценка: Значительный]
        - Риск: Искажение [Оценка: Незначительный/Значительный]
        - Риск: Потеря [Оценка: Незначительный/Значительный]
        - Риск: Обесценивание [Оценка: Незначительный]
    -> Конфиденциальные данные
        - Риск: Утечка [Оценка: Критический]
        - Риск: Искажение [Оценка: Критический]
        - Риск: Потеря [Оценка: Значительный/Критический]
        - Риск: Некачественные данные [Оценка: Значительный]
        - Риск: Обесценивание [Оценка: Значительный]
    -> Секретные данные
        - Риск: Утечка [Оценка: Критический]
        - Риск: Потеря [Оценка: Критический]
        - Риск: Искажение [Оценка: Критический]

Уровень 4: Обоснование (Под каждым риском/оценкой)
    -> Публичные данные -> Искажение [Незначительный]
        - Обоснование: Искажение публичных объявлений может вызвать временную путаницу или небольшой репутационный ущерб, легко исправляется.
    -> Публичные данные -> Некачественные данные [Незначительный]
        - Обоснование: Неточности в публичных описаниях могут разочаровать клиентов, но прямой ущерб безопасности минимален.
    -> Внутренние данные -> Утечка [Значительный]
        - Обоснование: Раскрытие внутренних процедур, данных о статусе объектов или исходного кода может помочь конкурентам или злоумышленникам, повлиять на операционную деятельность или безопасность.
    -> Внутренние данные -> Искажение [Незначительный/Значительный]
        - Обоснование: Искажение внутренних расписаний может вызвать сбои в работе (незначительно). Искажение исходного кода перед развертыванием (если классифицирован здесь) - значительно.
    -> Внутренние данные -> Потеря [Незначительный/Значительный]
        - Обоснование: Потеря внутренних документов может затруднить работу, но часто данные восстановимы. Потеря уникального исходного кода без бэкапов - значительна.
    -> Внутренние данные -> Обесценивание [Незначительный]
        - Обоснование: Устаревшие внутренние отчеты или процедуры снижают эффективность, но не несут прямого вреда.
    -> Конфиденциальные данные -> Утечка [Критический]
        - Обоснование: Прямое нарушение законодательства о ПДн (152-ФЗ), огромный репутационный ущерб (пример конкурента), штрафы, потеря доверия клиентов и собственников. Утечка учетных данных ведет к компрометации аккаунтов. Проблемы с API партнеров усугубляют этот риск.
    -> Конфиденциальные данные -> Искажение [Критический]
        - Обоснование: Неверные ПДн приводят к операционному хаосу, неверным счетам/услугам (описанная проблема "данные другого клиента"). Неверные финансовые данные ведут к ошибкам в учете и юридическим проблемам.
    -> Конфиденциальные данные -> Потеря [Значительный/Критический]
        - Обоснование: Потеря клиентских данных нарушает обслуживание, может нарушать требования к хранению. Потеря финансовых данных критична. Риск снижается бэкапами, но отказ восстановления делает его критическим.
    -> Конфиденциальные данные -> Некачественные данные [Значительный]
        - Обоснование: Дублирование и противоречивость ПДн (из-за множества точек регистрации) приводят к неэффективности, ошибкам (как в ЛК), мешают развитию data-driven сервисов (BI/ML/AI).
    -> Конфиденциальные данные -> Обесценивание [Значительный]
        - Обоснование: Устаревшие или неверные ПДн снижают ценность данных для бизнеса (персонализация, аналитика), что тормозит развитие новых сервисов.
    -> Секретные данные -> Утечка [Критический]
        - Обоснование: Компрометация ключей API или админских учеток дает злоумышленникам контроль над критическими системами, доступ ко всем конфиденциальным данным, возможность мошеннических операций (платежи, регистрация), полный отказ систем.
    -> Секретные данные -> Потеря [Критический]
        - Обоснование: Потеря ключей шифрования делает данные невосстановимыми. Потеря критических учетных данных блокирует доступ администраторам, парализуя управление.
    -> Секретные данные -> Искажение [Критический]
        - Обоснование: Изменение критических ключей или учетных данных может перенаправить операции к злоумышленникам или заблокировать легитимный доступ.
```

**3. Визуализация (с использованием draw.io):**

Теперь вы можете использовать draw.io (или аналогичный инструмент) для визуального создания этой интеллект-карты.

1.  Создайте центральную фигуру с надписью "Безопасность данных PropDevelopment".
2.  Проведите соединительные линии к четырем основным ветвям: "Публичные данные", "Внутренние данные", "Конфиденциальные данные", "Секретные данные".
3.  Под каждой ветвью категории добавьте фигуры для перечисленных примеров данных.
4.  От каждой ветви *категории* (не от примеров) проведите подве́тви для каждого соответствующего "Риска". Обозначьте ветвь названием риска и добавьте "[Оценка: ...]" в ту же фигуру или в связанную.
5.  От каждой фигуры риска/оценки проведите финальную подве́твь, содержащую подробное "Обоснование".

Эта структура напрямую отвечает на ваш запрос: классифицирует данные, определяет риски для каждой категории, оценивает их с обоснованием, основанным на специфическом контексте и проблемах PropDevelopment.
